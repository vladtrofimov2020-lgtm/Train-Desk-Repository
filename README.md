## 2. Назначение и цели создания ИС

### 2.1 Назначение системы

ИС «Расписание пригородных поездов» предназначена для автоматизации поиска, просмотра и сопровождения сведений о движении пригородных поездов. Система должна использоваться пассажирами для получения актуальной информации о рейсах, а администратором — для ведения справочников станций, поездов, маршрутов и расписания.

Вид автоматизируемой деятельности: информационное обслуживание пользователей и учет расписания движения пригородных поездов.

### 2.2 Цели создания системы

Целью создания системы является повышение удобства получения информации о пригородных поездах и снижение времени поиска нужного рейса. В результате разработки должны быть достигнуты следующие показатели:

- поиск подходящего поезда по станции отправления, станции прибытия и дате должен выполняться не более чем за несколько секунд при учебном объеме данных;
- пользователь должен получать сведения о времени отправления, времени прибытия, длительности поездки, маршруте и днях следования;
- администратор должен иметь возможность добавлять, изменять и удалять сведения о станциях, поездах, маршрутах и рейсах;
- данные должны храниться в структурированном виде и восстанавливаться после повторного запуска программы;
- интерфейс должен быть понятным для пользователя, не имеющего специальных технических навыков.

Критериями достижения целей являются успешное прохождение функционального тестирования, корректное отображение расписания по контрольным запросам и отсутствие критических ошибок при вводе некорректных данных.

## 3. Характеристика объекта автоматизации

### 3.1 Краткие сведения об объекте автоматизации

Объектом автоматизации является процесс предоставления и сопровождения информации о расписании пригородных поездов. В традиционном варианте пользователь получает сведения из бумажных таблиц, объявлений, справочных окон или разрозненных электронных источников. Это увеличивает время поиска и повышает вероятность ошибки при выборе маршрута.

В рамках учебного проекта объект автоматизации представлен набором данных о станциях, маршрутах, поездах и рейсах. Сведения должны включать названия станций, номера поездов, время отправления и прибытия, промежуточные остановки, дни следования и дополнительные примечания.

### 3.2 Условия эксплуатации

Система должна эксплуатироваться на персональном компьютере пользователя в учебной среде. Первая версия системы создается как консольное приложение. В дальнейшем допускается развитие системы до настольного или веб-приложения.

Окружающая среда эксплуатации: операционная система Windows или Linux, установленная среда выполнения выбранного языка программирования, доступ к локальному файлу базы данных или иному хранилищу данных.

## 4. Требования к ИС

### 4.1 Требования к системе в целом

#### 4.1.1 Требования к структуре и функционированию системы

Система должна иметь модульную структуру. Минимальный состав системы включает:

- модуль пользовательского интерфейса для ввода запросов и отображения результатов;
- модуль обработки запросов для поиска, фильтрации и сортировки рейсов;
- модуль хранения данных для работы со справочниками и расписанием;
- административный модуль для добавления, изменения и удаления данных;
- модуль проверки корректности вводимых данных.

Система должна поддерживать режим просмотра расписания и режим администрирования. В режиме просмотра пользователь выполняет поиск рейсов и просматривает информацию. В режиме администрирования выполняется редактирование справочников и расписания.

#### 4.1.2 Требования к численности и квалификации персонала системы

Пользователями системы являются пассажиры и администратор расписания. Пассажир должен обладать базовыми навыками работы с компьютером. Администратор должен знать структуру расписания, правила заполнения данных и порядок работы с административными функциями.

Для эксплуатации учебной версии достаточно одного администратора. Работа пользователя с системой выполняется по запросу, работа администратора — по мере необходимости обновления данных.

#### 4.1.3 Требования к надежности системы

Система должна корректно обрабатывать типовые ошибки ввода, включая отсутствие станции в справочнике, неверный формат времени и запрос маршрута, для которого отсутствуют рейсы. При возникновении ошибки пользователь должен получить понятное сообщение без аварийного завершения программы.

Данные расписания должны сохраняться после завершения работы программы. При сбое во время выполнения операции изменения данных не должно происходить частичное повреждение справочников. Рекомендуется использовать резервное копирование файла данных перед массовым обновлением расписания.

#### 4.1.4 Требования к эргономике и технической эстетике

Интерфейс системы должен быть оформлен единообразно. Команды меню должны иметь понятные названия. Результаты поиска должны выводиться в табличном виде с выравниванием по столбцам. Сообщения об ошибках должны описывать причину ошибки и возможное действие пользователя.

#### 4.1.5 Требования к защите информации

Для функций администрирования должна быть предусмотрена простая проверка прав доступа, например ввод пароля администратора. Пользовательский режим не должен позволять изменять данные расписания. При хранении данных необходимо исключить случайное удаление справочников обычным пользователем.

### 4.2 Требования к функциям (задачам), выполняемым системой

Система должна выполнять следующие функции:

1. поиск пригородных поездов по станции отправления и станции прибытия;
2. поиск рейсов по дате, времени отправления и времени прибытия;
3. вывод списка найденных рейсов с номером поезда, маршрутом, временем отправления, временем прибытия и длительностью поездки;
4. просмотр подробной информации о рейсе, включая промежуточные остановки и дни следования;
5. сортировка найденных рейсов по времени отправления, времени прибытия или длительности поездки;
6. ведение справочника станций;
7. ведение справочника поездов и маршрутов;
8. ведение расписания рейсов;
9. проверка корректности вводимых данных и вывод сообщений об ошибках.

Временной регламент выполнения основных функций: поиск и вывод результатов должны выполняться без заметной задержки для учебного набора данных; операции добавления и изменения записи должны завершаться после подтверждения пользователя.

Отказом функции считается невозможность получить корректный результат при правильных исходных данных, потеря сохраненных сведений, аварийное завершение программы или отображение заведомо неверного расписания.

### 4.3 Требования к видам обеспечения

#### 4.3.1 Требования к информационному обеспечению

Информационное обеспечение системы должно включать следующие основные сущности:

- станция: код станции, наименование станции, регион или направление;
- поезд: номер поезда, тип поезда, примечание;
- маршрут: станция отправления, станция прибытия, перечень промежуточных остановок;
- рейс: поезд, маршрут, дата или дни следования, время отправления, время прибытия, платформа при наличии данных;
- пользовательская роль: пользователь или администратор.

Данные должны храниться в табличной форме в локальной базе данных SQLite либо в файлах структурированного формата. Структура данных должна исключать дублирование станций и обеспечивать связь рейсов с маршрутами и поездами.

#### 4.3.2 Требования к лингвистическому обеспечению

Пользовательский интерфейс, сообщения программы и документация должны быть выполнены на русском языке. Названия станций должны храниться в кодировке UTF-8. Ввод команд должен быть организован через меню или понятные текстовые команды.

#### 4.3.3 Требования к программному обеспечению

Первая версия системы разрабатывается как консольное приложение. Для реализации допускается использовать язык программирования высокого уровня, например Python 3.x, C# или Java. В рамках данного ТЗ рекомендуется использовать Python 3.x и SQLite, так как данные средства подходят для учебной реализации и не требуют сложной настройки сервера.

Программное обеспечение должно быть разделено на классы и модули, отвечающие за данные, бизнес-логику, пользовательский интерфейс и работу с хранилищем. Код должен содержать понятные имена классов и методов, а также комментарии к основным функциям.

#### 4.3.4 Требования к техническому обеспечению

Для работы учебной версии системы требуется персональный компьютер или ноутбук со следующими минимальными характеристиками:

- процессор с частотой не ниже 1 ГГц;
- оперативная память не менее 2 ГБ;
- свободное место на диске не менее 100 МБ;
- операционная система Windows 10/11 или современный дистрибутив Linux;
- клавиатура и монитор для работы с консольным интерфейсом.
